# Decision log: branch `feat/vision-transform`

Pixel (camera above the table) -> x / y in Fairino `base_link`, for the control loop. Replaces the scratch tool
`pix2table` (not in git; lab test with 4 ArUco tags: 5-7 mm). Robot facts (frames, tool geometry, gripper) live in the
decision log of branch `feat/robot-motion-gripper`. Units: metres / radians in code, mm only in logs.

## 1. Decisions

| # | Topic | Decision | Why / options |
|---|---|---|---|
| V-1 | Branch | Orphan branch `feat/vision-transform`, worktree `~/hackathon/wt/feat-vision-transform/` | Same pattern as the other sub-projects; merged later with `--allow-unrelated-histories` |
| V-2 | Interface | **Service** `/vision/pixel_to_table` (several points per call) | One question, one answer, pure maths < 1 ms. Topic pair: caller must match replies to requests, no reply guarantee. Action: goal / feedback / cancel unused. User: "u decide" |
| V-3 | Names | Package `hk_fr5_vision` (node `vision_transform`, calibration app), interfaces in own package `hk_fr5_vision_interfaces` | Own interfaces keep the branch independent (vs `hk_fr5_interfaces` on the motion branch = cross-branch dependency until the merge) |
| V-4 | Environment | Own pixi env: `pixi.toml` / `pixi.lock` copied from the motion branch, same dependency list; `build` task = our 2 packages only; no Fairino driver path | Install from the cache 1.35 s, no extra disk (tested). Sharing the motion env needs a wrapper (activation sources the motion `install/`), new deps would land on the motion branch. Merge later: keep the union |
| V-5 | Explicit deps | `py-opencv 5.0.0`, `aiohttp 3.14.5`, `numpy 2.5.4`, `pyyaml 6.0.3` pinned (`pixi add`) | They were only transitive (via `ros-humble-desktop`); lock package list unchanged |
| V-6 | Method | Homography table plane <-> image from ArUco tag centres (`DICT_5X5_50`, fixed tag IDs only), least squares with 4-6 tags (2 in the middle for accuracy), C920 on USB | Proven in pix2table. **Focus is fixed** (user: autofocus off) -> no focus handling. Lens undistortion only if the accuracy is not enough |
| V-7 | Calibration storage | `hk_fr5_vision/config/calib.yaml`: homography, image size, tags (pixel + world), error per tag, RMS, camera name, date. Previous file kept as backup. **Committed after a good calibration** (user) | The node needs no camera and no tags after calibration; teammates get the same values |
| V-8 | Runtime node | `vision_transform` loads `calib.yaml` at start, reloads it when the file changes; no valid calibration -> `success = false`. Reply flags points outside the calibrated tag area (extrapolated) | Recalibrate without restarting the project |
| V-9 | Record current tcp | Calibration app: button per tag row fills x / y from the real robot: read-only client on the controller state port 20004 (robot in manual mode, hand-guided onto the tag). tcp = flange pose + R * (0, 0, 0.1129); pendant frame -> `base_link` = x, y negated. Warning if the tool tilts > ~2 deg. Fallbacks: pendant values typed in (x / y negated), direct entry | User workflow: open app, connect camera + robot, hand-guide tcp to a tag, record, all tags, fit, save. **Our bringup must not run while hand-guiding** (controller can jump back to the last commanded position) |
| V-10 | Camera ownership | Only the calibration app opens the camera; close it before the board detection runs | Two processes cannot open the C920 at once |
| V-11 | Calibration app | aiohttp + one HTML / JS / CSS page, no framework, no build step; polished UI (light / dark, overlay drawn in the browser). **Calibrate**: tag status (seen / stable, pixel centre = running average while visible, V-15), robot connection status (port 20004, manual mode), per tag row "record current tcp" 2-3x (average + spread, > 2 mm -> redo), fit (rms with / without lens term, `lens_k`, lens effect in mm, per-tag error, suspect hint), save. **Verify** (V-19). **Test**: click a pixel -> x / y + inside. Camera reconnect, runs without ROS, shows the loaded calibration + its verification. **No robot motion from the app** (go-to dropped with V-19 B) | User: robust and beautiful; features reviewed as we go. Updated with V-15 / V-18 / V-19 |
| V-12 | TCP for record | **Joints from port 20004 (`jt_cur_pos`, deg) + own forward kinematics (numpy)**: FR5 joint chain copied from the vendor URDF + our tool (flange -> cup tip 0.1129 m along flange z, no x / y offset), numbers in config with their source. `flange_cur_pos` from the same packet only as a cross-check (verifies the packet layout + pendant frame, VT1) | The Fairino web app / controller pose stops at the flange (no tool set). motion_shell gets the tcp via TF (robot_state_publisher FK on /joint_states with our URDF), which needs the bringup = not allowed while hand-guiding. Options: A flange pose + 112.9 mm (needs the pendant RPY convention for tilt, VT2), **B own FK (user)**: same kinematics as MoveIt (model errors cancel), result directly in base_link, testable offline vs the motion sim TF, C tool on the pendant (changes shared controller config) |
| V-13 | calib.yaml file handling | Placeholder `calib.yaml` (`calibrated: false`) committed, so the file is always installed; `save()` = temp file + rename (node never reads half a file), follows the symlink-install chain (install -> build -> **src**), keeps `calib.yaml.bak` (`*.bak` in `.gitignore`). Units in the file: metres | A rename on the installed path would replace the symlink and leave the committed source file unchanged; a file created after the build would not be installed at all |
| V-14 | Fit quality per tag | Per tag `err_mm` (residual) + `drop_rms_mm` (rms of the OTHER tags without this one, 6+ tags); `suspect` = tag whose removal makes the rest fit (rms > 2 mm, removal halves it, 3x clearer than any other tag), else None. A hint (re-record this tag), not proof | Offline (lab homography as the true camera, 0.5 px noise, 6 tags, 8 seeds x 300 random cases): wrong tag < 1 %, found 30 mm ~86 %, 20 mm ~77 %, 10 mm ~38 %, 5 mm ~3 %. Rejected: leave-one-out prediction error (blamed corner tags: 1 / 6 right, 5 mm on clean data), largest residual (4 / 6). Small errors (<= 10 mm at a corner) are absorbed by the fit (rms 1.4-1.8 mm vs 0.4 mm noise): the real check is the moving-tag accuracy test (VT3). 0.5 px noise: 6 tags worst probe error 1.06 mm mean vs 4 tags 1.26 mm |
| V-15 | Operator error (tcp placed by hand on the tag centre) | **2-3 recordings per tag** (lift, re-place, record), averaged; the app shows the spread per tag (> 2 mm -> redo). Tag pixel centre = running average over all frames where the tag is visible (the gripper hides the tag while the cup sits on it). Printed centring target (35 mm ring + crosshair) not used for now | User: the camera detects the tags easily, so repeat the robot side. Random placement errors average out (sim: recording 1.5 -> 3 mm costs +0.4 mm with 8 tags); a SYSTEMATIC offset does not, only the moving-tag accuracy check (VT3) shows it |
| V-16 | Tag count | **8 tags** (4 corners + 4 spread inside: 2 middle + 2 edge, or the 4 edge midpoints) | Sim, homography only, strong lens distortion (k1 0.10): 4 tags 5.6 mm mean / 9.8 mm 95 %, 6 tags 5.0 / 8.7, 8 tags 4.5 / 7.6, 9 tags 4.6 / 7.7 (no gain over 8). 4 corners + strong distortion matches the lab result (5-7 mm): the lens is likely the main error |
| V-17 | Lens distortion (plan B, sim) | Homography + 1 radial lens term k fitted from the same tags (p_u = c + (p_d - c)(1 + k r^2), c = image centre, 1-D search over k + least-squares homography). **Result, 8 tags, 1 mm recording, 0.5 px noise, 200 runs (mean / 95 %, mm): no distortion A 0.86 / 1.56, B 0.99 / 1.76; k1 0.05 A 2.37 / 3.97, B 0.94 / 1.67; k1 0.10 A 4.43 / 7.35, B 0.91 / 1.64; k1 0.10 + k2 0.03 A 4.83, B 0.95; barrel k1 -0.08 A 3.43, B 0.93; k1 0.10 + 2 mm recording A 4.55, B 1.65.** Truth used a different formula and an off-centre optical centre (+20 / -15 px), so B is robust to model mismatch | B beats A by 2.5-5x whenever the lens distorts, costs ~0.1 mm when it does not. Adopted: V-18 |
| V-18 | Lens term adopted (V3b) | **B always** (user): `calib.py` corrects pixels with one radial term `lens_k` (fitted with 6+ tags, else 0; search +-1.5, at the limit -> fit refused) then the homography. `calib.yaml` + `lens_k`, + `rms_homography_only_mm` (plan A, info). Leave-out fits for the suspect hint refit k too | Tests (8 tags, 0.5 px noise, distorted camera with another formula + off-centre centre): k1 +0.10 mean 0.54 mm / worst 1.84 mm (4 tags without lens term 5.0 mm), k1 -0.08 0.49 mm (4.3); fitted k sign right in all runs; ideal lens 8 tags 1.00 mm vs 4 tags 1.23. Suspect hint with a FIXED k in the leave-out fits dropped to 47 % found at 30 mm (k bends towards the bad tag) -> refit k: 30 mm found 93-96 %, 10 mm 50-59 %, wrong 0 / 1800 (3 seeds). Fit 161 ms, apply 100 points 0.09 ms |
| V-19 | Verification (frozen, user) | **A: hand-guide verification** in the app: a verification tag (not one of the fit tags, e.g. 6) placed at 5-6 spots spread over the pick area + near the edges; per spot the camera gives the PREDICTED x / y (tag seen before the cup covers it), hand-guide + record gives the ACTUAL x / y (port 20004, bringup off); error per spot, mean / max, pass if **mean <= 2 mm and max <= 4 mm** (defaults, configurable). Hints on fail: all errors shifted the same way = systematic placement offset; growing towards the edges = lens / corner tag; one spot = re-check it. Passed result saved as `verification` in `calib.yaml` (committed with it). Lens shown as `lens_k`, rms with / without the lens term and `lens_effect_mm()` (difference to a homography-only fit at the tag outline: ideal lens ~0.05 mm, sim k1 0.10 6.7 mm) | Options: A hand-guide (no motion, mm numbers, same tools, ~1 min per spot), B go-to with the bringup (whole chain incl. MoveIt + driver, judged by eye, mode switch, robot moves) -> **user: A, B dropped**. Limits: sim expects ~1 mm + ~1 mm operator error in the verification itself |

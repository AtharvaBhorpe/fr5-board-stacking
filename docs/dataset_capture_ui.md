# Keyboard capture from the Logitech ROS stream

This UI subscribes to the existing scene driver; it does not open another USB
camera connection. It requires no robot movement and no GPU model. Start the
camera driver separately only if /scene/image_raw has no publisher.

```bash
./.tools/pixi run --frozen -e camera-ros scene-camera
```

In another project terminal:

```bash
./.tools/pixi run --frozen -e camera-ros python scripts/capture_board_dataset.py \
  --scene 13 --priority --notes "Targeted board arrangements; final Logitech mounting"
```

Click the window so it receives keyboard events. S saves the original-resolution
displayed frame, N/P change the intended guide scene, and Q quits. The trackbar
can jump to any scene. Priority mode restricts N/P to the guide's 32 priority
arrangements. Without --priority, navigation covers all 100 layouts. Scene 0 is
available for additional arrangements not in the guide. S does not advance the
guide automatically. Stale images and repeat saves of the exact same source
frame are rejected. The preview may be resized; saved image pixels are not.

The terminal prints the new session path under .local/datasets/webcam_capture_*.
Each sample is self-contained under samples/capture_*/ with a uniquely named raw
PNG and metadata.json. images/ contains links/copies of webcam PNGs only for CVAT.
Session and sample JSON preserve:

- Original image header, ROS timestamp, receipt/save time and SHA256.
- Original image resolution and class dimensions in millimetres.
- Closest CameraInfo within 100 ms, or an explicit missing/mismatch warning.
- Observed camera parameter values and their observation time when the ROS
  parameter service is available. The snapshot is refreshed every five seconds;
  parameters are not asserted to be measured anew for each frame.
- Copies and hashes of camera/calibration configuration files. Copying candidate
  calibration does not validate it.
- Intended guide scene, suggested group, and operator notes. Intended board poses
  and group identity are not confirmed physical measurements or annotations.
- Sharpness/brightness diagnostics without an unvalidated quality cutoff.

Add --with-wrist to subscribe to RGB, aligned raw depth and CameraInfo. Only
messages within 100 ms of the scene image are attached; raw depth is stored in
NPY with source encoding/dtype and unverified unit-scale status. This is timestamp
association, not hardware synchronization. Add --with-robot to save nearby measured
JointState data and attempt base_link-to-flange/tcp TF at the image timestamp.
Absent/stale optional data is recorded as missing instead of fabricated. NaN joint
velocity/effort fields become JSON null. No real-hardware or calibration validity
is asserted from the presence of a ROS topic.

Upload images/ to CVAT; keep samples/ and configuration_snapshot/ locally. Label
actual visible board/hand instances in CVAT. The guide contents are instructions,
not ground truth, and no mask is automatically generated by pressing S.
